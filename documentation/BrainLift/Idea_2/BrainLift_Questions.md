# DeskResearcher – User Research Questions

## 1. Primary User Profile

- Who is the target user? (e.g., frontend devs, full-stack, solo devs)
  Focus on **frontend and full-stack developers in small-to-medium teams** as your primary target, with **solo developers** as a secondary audience. Tailor DeskResearcher’s messaging to emphasize time savings, actionable user insights, and integration into coding workflows (e.g., IDE plugins, desktop notifications). Highlight how it empowers devs to push back on misaligned feature ideas with data-driven arguments.

- Are they building new features, fixing bugs, or optimizing?
  DeskResearcher’s core users are primarily **building new features**, with **optimizing** as a secondary focus. The tool’s real-time user signal tracking and AI-driven insights are most valuable when devs are designing or refining features to align with user behavior, addressing the problem of misaligned top-down ideas. To maximize appeal:
  - **Position DeskResearcher** as a tool for devs building or iterating on features, emphasizing how it grounds their work in user data.
  - **Highlight Optimization Use Cases**: Show how the insight feed helps identify underperforming features for UX or performance improvements.
  - **Acknowledge Bug Fixing Indirectly**: Note that user feedback might surface recurring issues, but don’t prioritize this in messaging, as it’s not the primary use case.

- How often do they interact with PMs or users directly?
  **Frontend and Full-Stack Devs**: Position DeskResearcher as a tool that reduces reliance on PMs for user insights, providing real-time data to inform feature development during frequent PM interactions. Highlight how it fills the gap created by rare user contact.
  **Solo Devs**: Market DeskResearcher as a time-saving solution that enhances their frequent user interactions by automating feedback aggregation and prioritization, eliminating the need for a PM intermediary.
  Messaging: Emphasize DeskResearcher’s ability to deliver user insights directly to devs’ workspaces, bypassing bottlenecks (PMs for team devs, manual analysis for solo devs) and aligning feature work with user needs

- Do they currently make user-informed decisions? How?
- **For Frontend and Full-Stack Devs**: DeskResearcher’s real-time insight feed and AI-driven feature tagging bypass PM bottlenecks and fragmented tools, delivering user data directly to devs’ workspaces. This enables user-informed feature development and optimization, countering top-down “shiny object” ideas.
- **For Solo Devs**: The tool automates feedback aggregation and prioritization, reducing manual effort and allowing devs to focus on building or optimizing features based on user needs.
- **Positioning**: Market DeskResearcher as a tool that empowers devs to make user-informed decisions independently (for frontend/full-stack) or efficiently (for solo devs). Highlight how it replaces fragmented, PM-mediated, or manual processes with a unified, real-time insight feed.
- **Messaging**:
  - For frontend/full-stack devs: “Stop guessing what users want. Get real-time, feature-specific insights to build and optimize what matters, without PM filters.”
  - For solo devs: “Turn scattered user feedback into actionable insights, so you can focus on building features users love.”

## 4. Workflow Integration

- Where should this tool appear? (tray app, editor, Slack, etc.)
- **Primary Integration Points**:
  - **Code Editor/IDE Plugin** (Top Priority):
    - Develop a VS Code/WebStorm extension to display a real-time insight feed in a sidebar or hover-over tooltips, showing user feedback (e.g., “navigation issues, per Intercom”) and impact metrics (e.g., “30% drop-off, per Amplitude”).
    - Integrate with Linear’s API to link insights to tickets and GitHub for code context.
    - Benefit: Embeds insights where devs spend most time (50–90%), reducing context-switching and ensuring user-driven feature development.
  - **System Tray App**:
    - Run DeskResearcher as a lightweight background app with notifications (e.g., “new user complaint, per Discord”) linking to detailed insights or Linear issues.
    - Sync data from Intercom, Slack, Linear, email, and analytics (GA, Amplitude).
    - Benefit: Non-intrusive, ideal for quick checks, especially for solo devs or multitasking team devs.
  - **Slack/Discord Integration**:
    - Deploy a bot to post prioritized insights in Slack (for team devs) or Discord (for solo devs) channels/DMs, e.g., “Top issue: slow checkout, per Intercom.”
    - Use Slack/Discord APIs to pull feedback and integrate with Intercom, Linear, and analytics.
    - Benefit: Embeds insights in communication workflows, enabling advocacy (team devs) or community engagement (solo devs).
- **Secondary Integration**:
  - **Linear Dashboard**: Enhance Linear issues with DeskResearcher’s AI-tagged user impact and pain points (e.g., “affects 20% of users”), but prioritize IDE/Slack for immediacy.
  - **Browser Extension**: Consider for UI testing workflows (e.g., showing Hotjar heatmaps), but less critical due to lower browser usage (15–20%).
- **Positioning**:
  - For frontend/full-stack devs: “DeskResearcher integrates with VS Code and Slack to deliver real-time user insights, so you prioritize features users need, not PM guesses.”
  - For solo devs: “Get user feedback in VS Code, Discord, or a tray app, unifying Intercom, email, and GA to focus on what matters.”

- When should insights be shown? (coding, planning, review)
- **Primary Timing**: **Coding**
  - **Why**: Devs are most receptive to insights while building features (50–90% of time), preventing misaligned efforts (40–65% low-adoption features).
  - **How**: Deliver insights via a VS Code plugin with a real-time feed, showing feature-specific feedback (e.g., “users find form complex, per Intercom”) and impact (e.g., “30% drop-off, per GA”), integrated with Linear, Intercom, and analytics APIs.
- **Secondary Timing**: **Planning**
  - **Why**: Insights during planning help prioritize user-driven features, countering PM biases (60% frontend, 45% full-stack reliance) and saving solo devs time.
  - **How**: Use a Slack/Discord bot to post insights (e.g., “top user issue: slow load, per Amplitude”) or tag Linear issues with impact/pain points, using APIs.
- **Tertiary Timing**: **Review**
  - **Why**: Validates features but is less impactful, as rework is costlier. Insights can guide iterations.
  - **How**: Show via system tray app notifications or Linear issue enhancements (e.g., “low engagement, per Mixpanel”).
- **Positioning**:
  - For frontend/full-stack devs: “DeskResearcher delivers user insights in VS Code during coding and Slack during planning, ensuring you prioritize what users need.”
  - For solo devs: “Get real-time feedback in VS Code or Discord while coding or planning, so you build features users actually want.”
- **Validation**:
  - Survey devs via r/webdev or Indie Hackers to confirm when insights are most useful (coding vs. planning).
  - Test a VS Code plugin beta with Intercom, Linear, and Amplitude integrations to validate coding-time impact.

- Should the tool be passive or send proactive alerts?
- **Primary Approach**: **Passive Delivery**
  - **Why**: Aligns with coding-heavy workflows (50–90% of time), minimizes disruptions, and addresses fragmented feedback (Intercom, Slack, Linear, GA) by providing on-demand insights.
  - **How**: Implement a VS Code plugin (sidebar/tooltips) and system tray app to display a real-time feed of user feedback (e.g., “users find form complex, per Intercom”) and impact metrics (e.g., “40% drop-off, per Amplitude”), integrated with Intercom, Slack, Linear, email, and analytics APIs.
  - **Timing**: Primarily during coding to guide feature development, secondarily during review for validation.
- **Secondary Approach**: **Proactive Alerts**
  - **Why**: Critical, high-impact issues (e.g., >20% user impact, recurring complaints) need immediate attention during planning to influence priorities (frontend/full-stack) or focus resources (solo devs).
  - **How**: Send filtered notifications via system tray app (e.g., “urgent: 30% churn, per GA”) or Slack/Discord bot (e.g., “top issue: slow UI, per Intercom”) during planning or review, using APIs with customizable thresholds.
  - **Timing**: Primarily during planning to shape priorities, secondarily during review for urgent fixes.
- **Positioning**:
  - For frontend/full-stack devs: “DeskResearcher delivers passive insights in VS Code for coding focus, with targeted alerts in Slack for critical user issues during planning.”
  - For solo devs: “Access user feedback passively in VS Code or a tray app while coding, with Discord alerts for high-impact issues to prioritize your work.”

## 5. AI Summarization & Automation

- What should be clustered? (feature, topic, severity, confusion)
- **Clustering Priorities**:
  - **Feature (Primary)**: Cluster feedback by specific features (e.g., “navigation,” “API endpoint”) for all segments to align insights with coding tasks, addressing vague feedback.
  - **Severity (Primary)**: Assign severity scores (high, medium, low) based on impact (% affected users) and frequency, critical for prioritization across all segments.
  - **Confusion (High for Frontend/Solo, Moderate for Full-Stack)**: Cluster confusion-related feedback for UX-focused tasks, especially for frontend/solo devs.
  - **Topic (Moderate for Solo, Lower for Others)**: Group feedback into themes for planning, less critical during coding.
- **Implementation**:
  - **Coding (Passive Delivery)**: Show feature, severity, and confusion clusters in a VS Code plugin (e.g., “Feature: Login, high severity, 30% drop-off, confusion in UI, per Intercom/GA”).
  - **Planning (Proactive Alerts)**: Send high-severity alerts via Slack/Discord (e.g., “High severity: Checkout, 40% churn, per Amplitude”) and show topic clusters for roadmap discussions.
  - **Review (Passive/Proactive)**: Display feature/severity clusters in Linear or tray app for validation, with alerts for critical issues.
  - **Automation**: Use NLP for confusion/topic detection and machine learning for severity scoring, integrating Intercom, Slack, Linear, email, Discord, and analytics APIs.
- **Positioning**:
  - For frontend/full-stack devs: “DeskResearcher clusters feedback by feature and severity in VS Code, so you build what users need, not PM guesses.”
  - For solo devs: “Automate feedback with feature, severity, and confusion clusters in VS Code or Discord, prioritizing what drives user engagement.”
- **Validation**:
  - Survey devs via r/webdev or Indie Hackers to confirm clustering preferences (e.g., feature vs. topic priority).
  - Test a VS Code plugin beta with Intercom, Linear, and Amplitude integrations, evaluating impact on reducing low-adoption features (40–65%).

- Should feedback be summarized or shown raw?
- **Primary Approach**: **Summarized Feedback**
  - **Why**: Saves time, reduces cognitive load, and delivers actionable, feature-specific insights during coding (50–90% of time) and planning, addressing low-adoption features (40–65%) and fragmented feedback.
  - **How**: Use AI (NLP) to summarize feedback from Intercom, Slack, Linear, email, Discord, and analytics into clusters (feature, severity, confusion), displayed in a VS Code plugin (coding), tray app (coding/review), or Slack/Discord bot (planning).
  - **Example**: “Summary: Login page, high severity, 30% churn, confusing UI, per Intercom/GA.”
- **Secondary Approach**: **Raw Feedback (On-Demand)**
  - **Why**: Provides context for complex issues or validation during planning/review, but less critical for daily coding due to time constraints.
  - **How**: Offer clickable links to raw feedback (e.g., full Intercom chats, Discord messages) in VS Code, tray app, or Slack/Discord, accessible when devs need deeper insight.
  - **Example**: Link to “User: Login button is too small” from a summarized insight.
- **Positioning**:
  - For frontend/full-stack devs: “DeskResearcher summarizes user feedback in VS Code and Slack for fast, actionable insights, with raw data on-demand for deeper context.”
  - For solo devs: “Get summarized feedback in VS Code or Discord to prioritize quickly, with raw comments available for nuanced planning.”

- Can the tool infer current feature from file/module name?
- **Feasibility**: DeskResearcher **can infer features** from file/module names with high effectiveness for frontend/solo devs and moderate effectiveness for full-stack devs, using VS Code’s API and NLP.
- **Implementation**:
  - **Primary**: Parse file/module names (e.g., CheckoutForm.jsx) with NLP in a VS Code plugin to infer features, cross-referencing with Intercom, Linear, and analytics for relevant insights (e.g., “Checkout form: 30% drop-off, per Amplitude”).
  - **Context Enhancement**: Use directory structure, Linear ticket titles, or code comments to resolve ambiguous names (e.g., utils.js in /api/payment → “payment”).
  - **Delivery**: Show summarized insights (feature, severity, confusion) in VS Code (coding), Slack/Discord (planning), or tray app (review), with raw feedback on-demand, per prior analysis.
- **Positioning**:
  - For frontend/full-stack devs: “DeskResearcher infers features from your code (e.g., NavigationBar.jsx) to deliver real-time user insights in VS Code, ensuring you build what users need.”
  - For solo devs: “Get feedback tied to your code (e.g., SignupForm.jsx) in VS Code or Discord, automating prioritization for your next feature.”
